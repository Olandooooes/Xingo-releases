## 场景与我的职责

桌宠的陪伴体验可以延伸到朋友之间的轻量互动：宠物离开本机，去朋友桌面到访，交换纸条，再返回并留下回忆。我独立开发产品，把这个过程落实为桌面交互、实时连接、两端状态和安装包交付。

产品获外滩黑客松二等奖，相关内容累计 5 万余播放，依据本人提供的经历材料。这里的播放量不是下载量或用户数；当前未附公开获奖证明和播放统计链接，不由此推导商业收入。

## 核心用户流程

```mermaid
flowchart LR
  A[本机桌宠] --> B[选择好友并出发]
  B --> C[实时服务协调]
  C --> D[好友桌面到访]
  D --> E[互动与纸条回复]
  E --> F[返回本机]
  F --> G[保留互动回忆]
```

*这是体验与状态流的概括示意，不是服务生产拓扑。*

真正需要协调的不是一段动画，而是两台电脑对“宠物在哪里、谁正在访问、何时返回”的理解；桌宠窗口、管理界面和连接状态也必须相互配合。

## 技术栈与开发工具

| 技术 / 工具 | 可核实用途 |
| --- | --- |
| Electron、JavaScript、HTML/CSS | 透明桌宠窗口、置顶、拖动、原生菜单及管理界面 |
| WebSocket / ws | 实时连接和跨设备访问消息；README 记录了断线重连与状态恢复 |
| Node.js / Express | 仓库服务端与接口开发依赖，不据此推断生产全部存储架构 |
| electron-builder / NSIS | Windows 便携包和安装器构建 |
| Node / Electron 测试脚本 | 交互、状态、界面、打包与多缩放比例检查入口 |
| GitHub Releases、SHA-256 | 版本归档、安装包分发与完整性核对 |

Electron 使桌宠窗口与管理界面可以共享 Web 技术，同时通过主进程调用窗口能力。仓库实际使用置顶、透明区域鼠标穿透和独立窗口；管理界面展开时需要调整交互行为，不能把整片区域持续穿透导致用户无法操作。

## 关键实现与难点

**桌面窗口不只是网页。**  
主进程根据桌宠、管理和访问模式调整窗口置顶与鼠标行为，另有到访窗口的创建、取消和完成路径。这说明动画生命周期和操作取消也要与系统窗口状态协调。

**跨设备访问需要恢复状态。**  
项目说明包含断线重连后恢复在途/到访状态。当前核查发现连续访问、离线通知、到达状态等测试脚本，能证明这些场景被纳入实现和检查；本次没有重新执行双设备网络测试，不能据此声称所有异常已解决。

**打包后的表现需要单独验证。**  
安装包是用户的真实运行环境。仓库为打包产物和界面状态保留独立测试入口，也包含不同缩放比例检查。开发环境启动成功不能替代正式安装、资源加载和窗口体验验收。
