# 销售报表自动化 · Salesforce → Python / SQL → Power BI

[← 作品集首页](../PORTFOLIO.md) · [相关：RPA](rpa.md)

> 企业数据工作案例。6 条产品线、约 6 小时至约 20 分钟来自本人工作自述；本次没有读取生产数据或复测耗时。

## 业务问题与任务

销售报表更新需要获取和整理 Salesforce 数据，再形成业务可用的报表。重复清洗、入库与刷新占用时间，处理链路需要能够持续运行，服务 6 条产品线的数据需求。

我的贡献是用 Python 清洗和处理数据，通过 SQL 入库并连接 Power BI，将数据获取、整理、存储和报表刷新串起来。

## 数据流与技术分工

```mermaid
flowchart LR
  A[Salesforce 数据] --> B[Python 清洗处理]
  B --> C[SQL 入库]
  C --> D[Power BI 报表与刷新]
  D --> E[业务人员查看]
```

*这是已知工作链路的概括示意，不表示 Salesforce API、调度器或具体数据库已经核实。*

| 技术 | 在本项目中的用途 | 尚未核实的细节 |
| --- | --- | --- |
| Salesforce | 业务数据来源 | 项目记录说明脚本自动拉取；API/认证方式、对象及字段未见实现证据 |
| Python | 清洗和处理数据 | 使用库、脚本组织、调度及异常处理 |
| SQL | 入库与报表数据衔接 | 数据库产品、表模型、增量或全量策略 |
| Power BI | 呈现与更新业务报表 | 具体指标、DAX / Power Query 范围、网关与刷新计划 |

采用这些工具的已知分工是将可重复的数据处理交给脚本和数据库，把结果交给业务报表消费。当前没有足够的选型记录证明曾做过性能对比或平台成本评估。

## 个人贡献与使用结果

工作材料记载我串联此链路，服务 6 条产品线，原约 6 小时流程缩短至约 20 分钟。这个数字仅描述原有报表处理任务的耗时自述，不扩展为全公司工作效率、人工岗位节省或营收影响。

GitHub 既有项目记录进一步说明任务为月会报表：原先 6 条产品线各约 1 小时手工处理，合计约 6 人时/月；新流程自述约 20 分钟。原流程包含下载、Excel 合并计算、更新图表与整理汇报材料。仍需核实新旧计时是否覆盖相同环节、数据量，以及是否包括人工核验和异常重跑。因此暂不计算年节省工时或推广为稳定的效率百分比。

## 验证、交付和维护边界

已有证据支持业务报表持续使用的工作经历，但没有拿到可以公开的数据对账记录、抽样检查方法或失败恢复日志。本页不把“能生成看板”当作已经验证所有指标正确。

数据来源、清洗规则和报表口径之间的一致性是进一步展示时的重点。后续应使用实际脱敏记录说明一条数据如何流入结果、口径如何确认、错误怎样发现；在取得这些材料前，不补写未经证实的数据质量告警或自动重试机制。

公开案例不附 Salesforce 原始导出、销售数据、账号配置或 Power BI 内部链接。
